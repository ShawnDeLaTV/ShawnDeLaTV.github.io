4G Frame Decoder

Résumé

Outil de traitement du signal et de décodage en Python permettant d'extraire des données utilisateur chiffrées à partir de flux de communication sans fil (OFDM, démodulation multi-couches et correction d'erreurs).

Voir le code

Ce décodeur spécialisé est conçu pour traiter des matrices de signaux complexes transmises sur des canaux OFDM (Orthogonal Frequency-Division Multiplexing). Il implémente des stratégies de démodulation et de décodage multi-niveaux pour extraire et déchiffrer les messages des flux de données. Le projet a été initialement développé en 2025 dans un cadre académique privé avant d'être migré publiquement.

Expertise & Compétences Validées

  • Traitement du signal : Manipulation de matrices complexes et extraction de signaux en environnement bruité via analyse spectrale et filtrage adaptatif.
  • Modulation numérique : Implémentation et décodage des modulations BPSK, QPSK et QAM-16 avec seuillage de décision adaptatif.
  • Correction d'erreurs (FEC) : Décodage syndrome de codes de Hamming(7,4) et décodage dur pour flux convolutifs avec correction automatique d'erreurs.
  • Réseaux Mobiles 4G : Décodage des canaux physiques PBCH, PDCCH, et PDSCH conformes aux standards 3GPP LTE.
  • Cryptanalyse : Validation d'intégrité par CRC polynomial et déchiffrement par algorithmes de chiffrement (César, substitution).
  • Traitement de fichiers : Parsing de flux CSV complexes, sérialisation de résultats et logging structuré d'opérations.

Pipeline de Traitement des Canaux

Le décodeur reproduit fidèlement la couche physique d'une station de réception en segmentant le traitement selon les canaux LTE/4G standards du 3GPP :

  1. PBCH (Physical Broadcast Channel) : Extraction des informations de contrôle globales de la cellule. Décode le Cell ID (identifiant unique), le nombre d'utilisateurs actifs et les paramètres de synchronisation de base. Ce canal est toujours transmis en QPSK pour robustesse maximale.
  2. PDCCH (Physical Downlink Control Channel) : Interprétation des messages de contrôle d'allocation de ressources. Pour chaque utilisateur détecté, extrait le schéma de modulation (MCS = Modulation Coding Scheme), les blocs de ressources (RB) alloués et l'indice de transport utilisé pour le décodage PDSCH.
  3. PDSCH (Physical Downlink Shared Channel) : Pipeline complet d'extraction de données :
    • Extraction du payload : Récupération des symboles IQ du bloc de ressources alloué
    • Démodulation : Conversion en bits selon le MCS (BPSK→1 bit, QPSK→2 bits, QAM-16→4 bits par symbole)
    • Correction d'erreurs : Application du décodeur Hamming(7,4) sur blocs de 7 bits
    • Validation CRC : Vérification de l'intégrité via polynomial (8, 16, 24 ou 32 bits)
    • Déchiffrement : Récupération du message en clair après suppression du chiffre appliqué

Algorithmes & Implémentations Clés

1. Démodulation Numérique (BPSK, QPSK, QAM-16)

La démodulation convertit les symboles complexes (I/Q) du domaine fréquentiel en séquences binaires. Chaque schéma utilise une approche de seuillage décisionnel basée sur la géométrie de la constellation : 

# Démodulation BPSK (1 bit/symbole) - décision sur partie réelle
def bpsk_demod(qamSeq):
    return [1 if x.real >= 0 else 0 for x in qamSeq]

# Démodulation QPSK (2 bits/symbole) - décision sur quadrants
def qpsk_demod(qamSeq):
    bits = []
    for symbol in qamSeq:
        bits.append(1 if symbol.real >= 0 else 0)
        bits.append(1 if symbol.imag >= 0 else 0)
    return bits

2. Code de Hamming (7,4) - Correction d'Erreurs

Le code de Hamming(7,4) détecte et corrige automatiquement jusqu'à 1 erreur binaire par bloc de 7 bits. Spécifications Techniques des Signaux

    
    

      

        
Structure OFDM

        
    
          
  • Sous-porteuses totales : 624 par symbole OFDM (bande large pour test)
    • 
          
  • Porteuses utiles : 312 centrées (rest pour gardes)
    • 
          
  • Espacement fréquentiel : 15 kHz par porteuse (standard LTE)
    • 
          
  • Durée symbole OFDM : ~66.67 μs (avec préfixe cyclique)
    • 
          
  • Blocs de ressources : 12 porteuses × 1 symbole = 1 élément de ressource (RE)
    • 
        

      

      

        
Format des Données d'Entrée

        
    
          
  • Format fichiers : CSV avec séparateur point-virgule (;)
    • 
          
  • Structure : Alternance [Re₀, Im₀, Re₁, Im₁, ...] pour chaque symbole
    • 
          
  • Précision : Nombres flottants 32-bit (complexes normalisés)
    • 
          
  • Ordre : Symboles en ordre temporel pour reconstruction correcte
    • 
          
  • Exemple : 0.707, 0.707, -0.707, 0.707, ...
    •

Limitations Connues & Cas d'Usage

    

      

        
Limitations

        
    
          
  • Correction d'erreurs limitée à 1 erreur par bloc Hamming
    • 
          
  • Pas d'égalisation de canal (assume canal AWGN idéal)
    • 
          
  • Pas de synchronisation fine d'horloge ou compensation de phase
    • 
          
  • Décodage hard (décisions binaires, pas soft-decoding)
    • 
          
  • Performance dégradée en présence de multi-trajets ou Doppler
    •
